# 原版 Qwen-Image-Edit 8 步 Lightning 前置实验协议

编制日期：2026-10-22（Asia/Shanghai）。本文件先冻结实验设计，实测数据与结论见配套结果文档；执行状态以原始日志和计划完成表为准。

## 1 本轮目标与范围

下载与原版 `Qwen/Qwen-Image-Edit` 匹配的 8 步 Lightning LoRA，确认当前开发环境能正确加载和推理；分离步数/调度、CFG 与 LoRA 的影响，测量完整请求耗时、DiT 调用次数和显存，检查文字、遮挡、细结构编辑中的质量问题。

本轮用于判断后续“边界感知局部计算加速”是否有值得投入的空间，不训练新 LoRA，不宣称完成局部稀疏执行器。三个公开演示输入与正式 Train/Val/Test 数据划分独立，不能据此宣布通用质量、无损或统计显著提升。

## 5 一致性、计时和资源口径

1. BF16、batch=1、约 1024² 面积且保持纵横比；使用官方条件图预处理，不将条件图额外缩为 512。
2. 每输入固定 seed `2026102201`，显式保存同一 packed 初始 latent，所有配置传入 clone，并记录 SHA256；相同 seed 不被当作独立样本。
3. 原版分组先运行，之后才加载 Lightning，最后才融合；融合后不再将该实例当作原版。
4. 正/负提示使用作者的单空格负提示；以真实 DiT 调用次数确认 CFG，而非只检查参数值。
5. 每请求新建 scheduler，保留完整配置、timesteps 和 sigmas。请求间不缓存条件编码、VAE 编码或研究 KV。
6. 优先所有组件常驻 GPU，统一启用 VAE tiling；使用 native PyTorch SDPA。不量化、不启用额外近似缓存、不编译。
7. 主计时从内存中源图与指令进入 pipeline，到 PIL 输出和 GPU 同步结束；包含预处理、编码、去噪、解码与转图，排除模型加载和 PNG 写盘。
8. CUDA events 分别记录 prompt 编码、条件 VAE 编码、DiT、scheduler 和 VAE 解码的区间时间；不将其称为纯 kernel 时间，也不把阶段之和强行等同端到端时间。
9. 每请求前同步 GPU、重置峰值显存统计，保留权重驻留及 allocator 缓存。分别报告 allocated/reserved，不能将其当作整个驱动进程显存。
10. 每配置先在 blocks_text 预热一次。三个输入各跑一次主测；A/D/E 在 blocks_text 补足三次计时。其他输入包含新形状的首次调用，单次时间只作探索性数据。

计划总量：15 条主测、6 条额外计时重复、5 条预热，共 26 条请求，预期 792 次 DiT 前向。预热不进入主质量或稳态均值。若异常中断，保留失败记录，不将失败伪装为完成。

## 6 质量与加速空间分析

- 原版 A 不是正确答案：单独观察是否完成指令、是否出现非预期改动，以及接缝、粘连、对象缺失。
- 计算各配置相对 A 的全图 MAE/PSNR/SSIM，以及相对输入的粗框、固定环带和远背景变化。若执行 LPIPS，记录实现、网络与权重；不将 RGB 乘黑色 mask 后的结果当标准区域 LPIPS。
- D/E 的差异用于衡量融合影响，不将融合带来的结果变化误写为不同随机种子。
- 全图变化范围只作诊断：错误背景漂移也会形成差异，不能自动当作应扩大的编辑区域或训练标签。
- 由 DiT 时间占端到端时间比例，估算进一步局部压缩的乐观上限；该上限尚未扣除控制器、索引、KV 与小矩阵开销，不能冒称已实现加速。
- 三输入、单生成种子不支持通用成功率、非劣性或统计显著结论。人工视觉检查属于非盲初查，不冒称双人盲评。

C 的环境回归为补充诊断，不加入原26请求的计时与质量均值。当前 `run_pilot.py` 在写出 adapter 元数据后删除观测列表，避免融合卸载后仍保留参数；实测历史版本与 SHA256 保存在 `attempts/attempt03_completed`。本轮 E 的显存仍按历史实测如实报告，不把修复后的预期节省伪装为实测。

本轮实际运行由独立 Python 脚本插桩完成，以获得中间张量形状与阶段数据；已使用仓库 Diffusers CLI 技能核验环境及能力。未提交、推送代码或创建 PR。

区域实现补充：ring16/32/64 的标签半径按输出短边/1024缩放，使用十字结构的累计L1膨胀；三个区域相互重叠，也可能和远背景重叠。不是互斥的固定真实像素环带。区域LPIPS使用全图距离图内平均，详见结果文档的指标定义。
