## 5 下一轮最小局部执行实验

### 5.1 先建立精确优化基线

首先确认 D/E 质量差异和耗时，选定经过验证的部署参照。核验并利用真正不依赖去噪状态的量，例如位置相关常量，以及冻结条件编码器 / VAE 的确定性输出。

必须区分两种情形：

- **单个新请求**：现有 pipeline 本来就只编码一次提示和条件图，不能把已有行为重复计为新优化。
- **重复同图同指令请求**：可以单列条件缓存命中实验，但需同时报告首请求、缓存构建、命中率与摊销成本，不能与无缓存的单请求混为主结论。

若缓存主干输入投影或旋转位置常量，需检查其真实依赖并验证等价性。主干深层条件 token 与目标 token 进行联合注意力后，表示会受当前去噪状态影响；跨步复用其 K/V 属于近似，不得命名为精确静态缓存。

### 5.2 正确性先于局部收益

| 检查 | 最小执行内容 | 通过证据 |
|---|---|---|
| 几何 | 记录实际 target / condition 高宽、latent 网格、pack 顺序、`img_shapes` 与原始位置索引 | 同一像素、latent 与 token 的映射可复核；无错位、越界或裁剪混淆 |
| 全选 | 局部执行路径在选中全部目标 token 时与完整路径比较 | 中间状态和最终结果差异满足预先冻结的数值容差；需同时测试重排 / scatter 路径，不能仅依靠全选直接回退掩盖错误 |
| 边界与新增 token | 核心区域扩大后，新激活 token 使用当前 latent 和原始位置进入计算 | 不是复制旧 hidden state 后直接宣称已经刷新 |
| 缓存与 CFG | 明确每层缓存对象、更新时间、失效条件和显存；原版 CFG 两路分离 | 无未初始化 token，无正负分支串用；Lightning CFG=1 不引入无必要的负分支 |
| 真实减少计算 | 记录实际 Q、K/V、MLP 张量形状及 profiler 证据 | 确实减少算子输入或执行，不能先全图算完再 mask 输出 |
| 状态复现 | 同一初态与动作可重复运行；相同状态的分支顺序不影响结果 | 缓存、RNG、scheduler 和 history 均正确重置 / 克隆 |

容差在验证数据上预先固定，并同时记录 latent 误差与图像误差；后续不得为了让失败实验通过而随结果放宽。正确性未通过时，停止质量与加速归因，先修复实现。

### 5.3 八步局部方案与区域对照

先采用保守安排：第 1 / 8 步全图，中间第 2–7 步允许局部计算；所有配置保持相同总步数、初始 latent、scheduler、提示和首尾全图约束。inactive 区域的近似复用策略需明确写入方法，不将其称为精确计算。

| 方案 | 区域与用途 |
|---|---|
| F | 全图，等价优化后的 Lightning 8 步参照 |
| R0 | 核心语义区域，检查最小区域的失败类型 |
| R1 | 预设固定膨胀，提供易复现的强规则参照 |
| R2 | 结构 / 接触关系引导扩展，检查用户提出的边界假设 |
| R3 | 与 R2 同 token 数的普通膨胀或预先规定的邻域选择 | 

R2/R3 的活动 token 数要相等或按固定 tile 的最小粒度报告实际差额，并维持相同刷新次数。不能把更大区域自然得到的质量改善都归功于边界选择。语义粗框仅用于本轮筛查；正式研究需补充独立的允许变化区与评估区标注。

原来的三个演示输入可以用于工程调试与失败定位；正式机制比较转入 Train / Val，不能将这些样例反复调优后的结果包装为独立测试。

### 5.4 用实际成本决定是否训练

设当前参照的 DiT 区间占端到端比例为 `p`。若保留两步全图，六步局部，极其乐观地假设局部步骤全部 DiT 时间按活动比例 `a` 线性缩放，则请求耗时比例下界约为：

`(1 - p) + p × (2/8 + 6/8 × a)`。

这是用于排除不现实目标的乐观估算，忽略了文本 / 条件 token、完整 K/V、索引、控制器和小矩阵低利用率等固定成本。实际结论必须由部分选区的微基准及端到端运行得出；缓存也要计入新增显存和初始化时间。

| 决策 | 建议条件 | 下一步 |
|---|---|---|
| Go：进入小样本收益学习 | 正确性通过；局部执行在明确质量约束下显示重复可见的净耗时收益；等面积区域选择也出现有意义的质量差异 | 先收集少量 Train 状态标签，再决定扩展到 32 请求；训练小型收益头 / 校正器 |
| Revise：调整实现或研究定位 | 算子减少但总耗时不降；缓存 / 索引占主导；边界扩展需过大；或 Lightning 原生质量不适合该类任务 | 优化粒度与固定开销；必要时以原版 50 步研究机制，将 Lightning 保留为强基线；先扩大验证案例，再决定是否继续 |
| Stop：停止当前局部执行路线的扩展 | 实现正确后，在多种合理区域和粒度下仍无收益空间，或质量明显退化且需接近全图才能恢复 | 停止增加训练和 RL 投入，保存负结果；重新评估课题范围。三个演示样例的失败不能单独证明整个方向不可行 |

初筛可以暂以约 10% 的端到端净收益作为值得继续投入的工程目标，但这不是已测性能承诺，也不是仅凭三次重复即可作出的统计显著性门槛。若改进只有数个百分点，应先确认计时噪声，再投入训练。

### 5.5 保持小样本与测试隔离

- 继续沿用正式 **Train32 / Val16 / Test64** 的源图分组隔离。若正式清单尚未建好，先建立清单和哈希；测试数据保持未接触状态。
- 前置训练先用嵌套的 8 / 16 / 32 请求规模，所有可训练模块均只使用对应子集。不能先用 32 请求训练校正器，再把其中 8 请求收益头称为纯 8 样本方法。
- 所有阈值、区域规则、数值容差、训练轮数和去留决定只依据 Train / Val；正式 Test 在方法冻结前不生成、不查看、不评分。
- Lightning 和原版数据、代码路径及结果分开记账；不同主干 / 步数上收集的标签不能混写为同一种教师标签。
- 在训练选区头之前，先证明结构区域与等面积普通区域存在差异；在引入 RL 之前，先证明短序列中存在监督学习难以覆盖的动作依赖，并保留同预算监督对照。

本周仅在通过门槛后安排新的实际 GPU 运行；不预写训练耗时、加速倍数或模型收敛结果。每次新增数据采集都同时记录请求数、种子、真实 DiT 前向、奖励 / 指标开销和失败重跑，避免只统计优化步骤而漏掉教师查询。
