# 同状态缓存误差归因：实测结论与研究方向调整

日期：2026-10-22。执行环境：zeta，用户确认的H800单卡；驱动显示NVIDIA L20Y，CUDA capability为9.0。使用原版Qwen-Image-Edit及其对应8步Lightning LoRA，融合后BF16推理。模型、输入、初始latent、R2计算区域、调度器和首尾全图刷新均沿用上一阶段。

**本轮最重要的发现：在这三个样例中，原局部执行器的主要输出误差出现在正在计算的活动区域。优先研究活动分支的旧上下文传播，比只修正区域外旧velocity更有依据。** 这支持保留局部加速方向并调整技术重点；尚未证明小样本校正器能以低成本恢复质量。

本轮实际完成12次生成、168次真实DiT前向：72次局部前向、72次同状态完整oracle、24次原生完整前向。另有两轮小模型校验，共192次tiny模型前向，不计入20B模型次数。全部请求成功，未出现OOM。冻结协议见[01_实验协议](01_实验协议.md)，逐步数据和终图指标见[数据摘要](01_误差归因数据摘要.md)。

## 1. 这次如何分离误差

在同一个当前latent、时间步和条件下，计算完整预测D与局部预测L。令M表示本步计算的目标token，R表示区域外保留的历史velocity。比较四种输出：

| 记录模式 | 区域内预测 | 区域外预测 | 含义 |
|---|---|---|---|
| D | 当前完整模型 | 当前完整模型 | 同状态完整预测；另用于推进D自身完整轨迹 |
| V | 当前完整模型 | 历史velocity | 保留区域外速度复用 |
| K | 当前局部模型 | 当前完整模型 | 保留活动分支的上下文近似 |
| B | 当前局部模型 | 历史velocity | 原局部执行器 |

V中的V指velocity；K中的K是对上下文近似的简写，包含历史attention Key和Value及其后续传播。K不是单独缓存Key的实验。V和K都调用了当前完整模型，属于带oracle的诊断，不是可部署加速算法。

主归因始终使用B自身轨迹上的当前状态：区域内误差为M(L−D)，区域外误差为(1−M)(R−D)。两项支撑不重叠，因此平方误差可相加。这是输出坐标的代数关系，不能解释为两种机制独立，也不能把最终图像或LPIPS变化相加。

另外让V、K各自从同一初始噪声生成完整轨迹，用于观察累积表现。它们后续的latent和缓存历史会分叉，因此跨轨迹误差份额不能相减为因果贡献。所有oracle使用本条轨迹的当前状态，不使用另一条完整轨迹的对应步预测冒充真值。

## 2. 主归因结果：活动区误差占主导

汇总B轨迹第2—7步，首尾全图步不纳入非零误差份额。速度误差使用FP32计算平方和；一步Euler能量另乘实际Δσ²，随后汇总。两者均不是最终累计误差。

| 输入 | R2活动目标比例 | 活动区速度误差能量份额 | 活动区一步Euler误差能量份额 | 活动区/非活动区单位元素MSE |
|---|---:|---:|---:|---:|
| 文字替换 | 26.82% | **91.90%** | **88.17%** | 30.94倍 |
| 衬衫改色 | 31.61% | **82.19%** | **79.66%** | 9.99倍 |
| 盘子去毛发 | 10.69% | **86.46%** | **84.69%** | 53.32倍 |

活动区只占目标token的约11%—32%，却承担约82%—92%的速度误差能量；其单位元素误差也明显更高。因此该结果不能用“活动区域面积大”解释。这里的active只计目标token，条件图像和文本一直参与计算，不计入该面积分母。

文字案例在第2个去噪步骤已出现活动区MSE约0.0351；去毛发案例在第6步升至约0.1259。错误并非仅在最后解码阶段才出现。第8步完整刷新虽然使该步局部预测等于同状态D，仍不能消除之前已累积的轨迹偏移。

这些结果支持将“活动区域如何接收过期背景上下文”列为主要问题。它们没有单独隔离每一层K、Value、文本分支或条件分支的贡献；不能表述为某一层KV已被严格证实是唯一原因。

## 3. Oracle干预后的终图表现

所有终图均与同轮D比较。继续使用上一阶段冻结的R0评价核心、公共边界带和allowed box；扩大计算范围不自动扩大允许改变的评价区域。D是计算参考，不是人工标注的理想编辑结果。

临时数值保真门槛保持为：全图LPIPS空间图均值≤0.02，且远背景相对D的额外源图MAE≤1/255。语义错误和明显接缝可独立否决数值通过。

人工观察：

- 文字：D和V均能读出“Tomorrow will be better”；K和B仍有错字、残留字符或字母形状异常。
- 衬衫：四组均完成蓝色衬衫这一高层编辑；V更接近D，但不能据此声称身份、手部、纹理完全一致，尚无正式身份指标或盲评。
- 去毛发：V的盘面更连贯；K和B仍可见与局部计算区域相关的亮度块。K/B的LPIPS通过再次说明，单一全图指标不足以判断边界质量。

| 同状态局部—完整配对 | 72条 |
| 首尾全图控制点 | 18/18完整输出逐位相等 |
| 实际scheduler步进核对 | 72/72与保存的Euler更新逐位相等 |
| 旧输出复现 | 3例D分别等于旧F、3例B分别等于旧R2，PNG哈希与RGB均一致 |
| 最终tiny校验 | FP32/BF16共8项通过，含动态非连续选区、全缓存隔离、V跨步写回 |
| 峰值GPU已分配显存 | 57.65 GiB |

| 12请求诊断耗时之和 | 108.80秒 |
| 配对局部前向耗时之和 | 25.72秒 |
| 额外oracle前向耗时之和 | 32.70秒 |

108.80秒包括编码、解码、同步、预测快照和部分指标计算，排除模型加载及PNG写盘；它不是稳态部署耗时，也不是完整研究工作流墙钟时间。25.72与32.70秒仅为相应子前向范围，不能据此计算部署加速。原生D的前向开销还包含在其请求耗时中。

真实模型诊断对完整velocity及三层少量位置的KV检查了oracle前后不变；tiny模型另对所有层完整KV、age、step、trace和输入做了全量检查。六个旧输出复现进一步支持原轨迹未受oracle查询影响，不能把抽样KV检查写成20B模型每个缓存元素都已比较。

Euler分析区分两种口径：Δσ×预测误差用于理想增量能量；实际BF16乘法和舍入后的下一状态另保存`rounded_euler_error`。真实scheduler只前进一次，没有为四个反事实输出连续调用真实scheduler。

分析过程中修正了一处字段命名冲突：派生CSV/JSON中的token数被同名标量元素数覆盖。修复后分别保存`active_count`与`active_scalar_count`；原始预测、SSE、比例和终图未变，模型未重跑。首版分析及日志保留在`attempts/analysis_v1/`。tiny校验首版与增加真实Euler核对后的第二版均保留，额外192次tiny前向已单列。

## 5. 对毕业设计方案的影响

“应适当扩大到边界更清晰的完整局部”仍有价值：上一阶段整盘闭合实验给出一例空间范围选择的正向线索。本轮则表明，即便R2边界固定，时间缓存误差仍能明显破坏活动区。因此研究目标应同时包含：

1. 选择语义和几何边界相对清晰的编辑计算域。
2. 控制域外上下文的陈旧程度，保证活动域获得足够可靠的信息。
3. 在严格记账的情况下，学习何处刷新或如何补偿上下文，并保留完整回退。

建议将当前技术假设写为：**在语义闭合局部区域上，通过上下文刷新和小样本补偿，降低局部执行相对完整8步编辑的质量损失，并获得可重复的净延迟收益。** “无损”和“单卡少量训练即可成立”仍属于待验证目标。

下一轮先比较预算一致的固定刷新与轮转刷新。如果可靠性收益只能靠大幅增加活动面积获得，且净加速降到目标以下，应据此收缩方向，而不是直接增加强化学习复杂度。小样本训练应优先围绕活动输出或上下文误差建立监督基线；强化学习须等待可执行动作、稳定质量代理和可度量的规则基线。

具体矩阵、训练集合划分和进入条件见[03_校正方案与后续计划](03_校正方案与后续计划.md)。本轮未训练校正器，未执行轮转刷新，未开展RL或SGLang迁移。
