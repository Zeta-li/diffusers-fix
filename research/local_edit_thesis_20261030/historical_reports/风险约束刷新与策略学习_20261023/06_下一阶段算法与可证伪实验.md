编制日期：2026-10-23。状态：**未执行的后续计划**。本文不启动模型、采集、校准或策略训练，不修改既有来源清单，也不把下表预算计入本轮已经完成的 **176 请求、1456 次真实 DiT**。后续执行前需另建目录、冻结协议、实现并通过 CPU 正确性检查；本文件不能代替执行预登记。

## 1 当前结果要求我们改变什么

本轮 [策略汇总](data/summary_refresh.json) 与 [动作等价审计](data/policy_equivalence_audit.json) 表明：在本次八个 Probe 来源及一个生成 seed 上，`STATIC=IL=PPO` 都执行 `FRONT=[15,3,0,0,0,0]`，八源 PNG 逐例一致。这不表示三个模型参数相同，也不表示它们对所有输入都等价，但足以否定本轮“PPO 提供了超出简单固定规则的终图收益”的主张。

FRONT 在首个中间步刷新全部目标，在第二个中间步刷新两组，之后四个中间步只刷新核心与余数 token。STATIC/IL/PPO 的 stale 目标读取共 95,256 token-step，全部对应旧表未观测的新锚点配对，实际为 **100% identity 回退**。当前收益不能归功于已训练的 Value 校准器。共享 96 条训练轨迹的 IL_PLUS 也未通过同一继续门，见 [共享数据对照](data/summary_shared_data_il.json)。

旧速度头在 Train8 终图上有 7/8 源 LPIPS 改善，但 Probe8 只有 1/8 改善；[C5](03_C5闭环误差诊断.md) 中降低训练源的同状态 velocity MSE，也没有自动带来跨来源终图质量收益。因此下一步优先采用固定 FRONT 和简单、可审计的闭式校准，不追加 PPO 轮数来掩盖这些负结果。

已观察到 Probe `495435` 蛋糕场景的酒杯周围出现明显粉色矩形边框。这是事后发现的开发问题，只能用于提出结构假设。后续必须检查所有源的整图、核心裁剪和选区叠图，不能只看核心均值或只展示改善案例；这张旧图不得重新包装成盲测。

## 2 三个待证伪假设与共同基线

| 假设 | 最小干预 | 可证伪结果 |
|---|---|---|
| H1：FRONT 新锚点缺少校准，使活动区域读取的上下文失真 | 固定同一时程、同一选区，仅校正 inactive raw Value 的临时读取 | 同状态 oracle-V 本身无明显收益，或闭式 V 校准未改善新来源终图，则不能继续把 Value 缺表当作主要解决方向 |
| H2：不重算区域的旧 velocity 是独立瓶颈 | 不改 K/V、年龄与刷新动作，仅校正返回的 U velocity | 标签 MSE 改善但 Dev16 终图或语义退化，则停止该输出校正，不以训练误差晋级 |
| H3：支持对象被局部核心切断，造成接缝 | 使用包含完整支撑结构的核心，与同 token 数普通扩展比较；两臂逐步刷新量及 FRONT 时程相同 | 结构臂未优于同面积对照，或只有扩大计算量才改善，则不能声称结构完整性有独立收益 |

共同部署基线固定为 `FRONT_ID`：原 R2 核心、原 SHA 四等组与余数、首尾完整计算、中间 `15/3/0/0/0/0`，stale 读取用 identity。先要求它复现本轮 FRONT 的输入、八步轨迹与 PNG 哈希。文本与条件图始终更新，attention 仍读取完整目标 K/V。它不运行 actor、风险网络、在线教师或无偿回退。

刷新时机在 H1/H2/H3 的主比较中保持不变，因此这些实验不能证明 FRONT 是最优时程。已有 FRONT 与 ROTATION 的比较同时改变时机、年龄和新锚点覆盖；不把它解释为单一机制的纯因果效应。本计划另外预留一个64DiT、两臂均identity的固定时程对照，独立计费，不依此重选主候选。

## 3 先只补 FRONT 实际使用的九种锚点配对

以下步号全部为零基：首尾是 0/7，中间是 1—6。固定 FRONT 下，第 1 步刷新所有目标；第 2 步刷新 G0/G1；第 3—6 步四组都不刷新。除每步必算核心及余数外，stale 读取只涉及：

- `(t=2,s=1)`；
- `(t=3,4,5,6;s=1)`，对应 G2/G3；
- `(t=3,4,5,6;s=2)`，对应 G0/G1。

合计九种配对。首个中间步没有 inactive 目标；仍安排一次 dense 控制调用验证全目标刷新路径，明确计费，不把它冒充采到了不存在的 stale 标签。初轮不收集全部 28 种可能历史配对，也不对未观测配对插值。配对与 layer 计数、实际覆盖和 identity 回退分别记录。

### 3.1 同状态标签合同

沿 `FRONT_ID` 自身轨迹推进。在每个中间步，用完全相同的当前 `z_t`、提示、条件图、真实 timestep 调用原 native dense 模型，教师不推进 scheduler、不改学生缓存或随机状态。

Value 标签的 `x` 必须来自该 token、该层在真实锚点 s 留下的 **raw Value 缓存**；`y` 是教师在同一当前 `z_t` 的对应原坐标 raw Value。velocity 标签的 `x` 来自真实原始 velocity 缓存，`y` 是同次 dense 输出。不能用 dense 自身另一条轨迹的 `z_t`，不能把当前 token 的未计算 hidden 当输入，也不能用校正后的估计覆盖真实缓存再当作新锚点。

每层、每状态总共最多抽取 128 个 inactive token，按真实 anchor 分层；两种 anchor 同时存在时各取最多 64 个，不足部分按冻结次序分配。无放回抽样由 `source/layer/t/anchor/seed` 的 SHA 决定，采集前写清单；不能按误差挑 token。保存每源的 `n,sum_x,sum_y,sum_x2,sum_xy,sum_y2`，FP64 流式累积，不落盘完整逐步 K/V。velocity 同时从同一次教师前向获得，不再增加教师调用。

学生/教师输入哈希、原始缓存前后哈希、真实年龄、indices、完整状态快照和 RNG 均须审计。真实 BF16 Euler 按已验证的 **0 维 FP32 delta Tensor** 公式重放，要求逐步精确一致，不用 Python float 乘法或宽松容差代替。CPU tiny 检查先覆盖动态刷新、九种 pair、同时间 identity、未见 pair identity、请求间清空及教师无写入。

旧 `ImageMoments.add_b_sums` 和 `ValueFittedExecutor` 已能表达非零历史 anchor；旧 `CalibrationCollector` 仍假设 anchor=0，不能直接用于本次采集。新锚点 collector、临时 velocity 仿射读取、联合 shadow 分支均是**待实现**，不能因为已有系数接口就称它们已完成。

### 3.2 两个有界闭式校准器

对每个 `layer,t,s,channel` 的 Value，先按源图等权汇总原始一、二阶矩，得到 `μx,μy,varx,covxy`，再求带 identity prior 的 ridge：

\[
a=\frac{\operatorname{cov}(x,y)+\lambda}{\operatorname{var}(x)+\lambda},\qquad b=\mu_y-a\mu_x.
\]

沿用已有候选 `η∈{10⁻⁴,10⁻²,1}`，`λ=η·mean_channel(varx)+10⁻¹²`，由训练源逐图留一、来源等权的归一化 SSE 选择；平局选更小 η。保留 `sum_y2` 才能独立重算留出 SSE。它是训练内模型选择，不是新留出评测。

拟冻结保守边界为 `a∈[0.5,1.5]`、`|b|≤0.25·RMS(y)+10⁻⁶`；先施加边界，再计算每个训练折的分数。边界不是质量保证，也使结果不再是无约束 ridge 的精确最优解；须记录被截断系数比例和截断前后误差。旧 `select_eta_loo` 不含这个过程，不能原样调用后声称已评价有界算法。同时间与未观测 pair 始终 `a=1,b=0`。

Value 只在注意力读取时临时应用 `a·Vcache+b`，不改 raw K/V、真实年龄或 anchor。velocity 使用相同公式，但独立按 `t,s,输出channel` 拟合，只替换本步返回的 inactive U 输出；活动 A 的预测、raw velocity cache 和真实锚点不变。两种校准分别选择 η，不作笛卡尔参数搜索，不重训旧 MLP。

完整模型为 60 层、raw Value 3072 通道；输出宽度从真实合同读取。九配对 Value 的纯 FP32 `a/b` 有效载荷约 12.66 MiB，但现有执行器仍分配完整 8×8 表，本轮实测表约 90 MiB；不能声称已实现稀疏表省显存。临时 affine 的显存读写、BF16 cast、gather 和同步均计入部署延迟。校准拟合、哈希、奖励工具、教师调用的墙钟和峰值显存另记，不能由推理秒数外推训练时间。

## 4 第一轮：Train8 内部机制筛查，先限制为 408 DiT

### 4.1 采集与交叉验证：112 DiT

旧 Train8 每源一条 `FRONT_ID`，8 次学生前向加 6 次同状态教师，共 `8×14=112 DiT`。沿当前 `FRONT_ID` 的九配对流式统计同时拟合 `V_NEW8` 和 `U_NEW8`。F 与 FRONT 终图优先复用本轮已有 PNG，但须校验模型、LoRA、seed、源图、latent、选区及时程；学生 FRONT 轨迹/PNG 必须精确复现。复用为新增 0 DiT，若不满足合同则停止而不是悄悄重生成。

内部代理继续门：相对 identity，留一结果的来源等权归一化 SSE 至少下降 10%，且至少 6/8 来源下降；数值有限、所有九配对有训练源覆盖、实际 stale token 覆盖率可审计。V 与 U 分别判门。若两者均未通过，停在 112 DiT，不扩大来源、不跑终图候选或 RL。

### 4.2 同一状态上的诊断：最多 104 DiT

仅用冻结 Train8 顺序的前四源，不能挑最差或最好的源。每源继续由 `FRONT_ID` 推进，逐步得到：原 L、同状态 dense D、仅临时替换 inactive Value 的 oracle-V、仅临时使用 `V_NEW8` 的 learned-V。每源 `8学生+6教师+6 oracle-V shadow+6 learned-V shadow=26 DiT`，四源共 104。U_NEW8 和 U-oracle 直接混合已有输出，不增加 DiT；所有影子分支禁止写回基线状态。

分别报告 A/U/全目标的 velocity SSE、relative RMSE、真实舍入后一步 Euler 误差、公共边界差和实际旧配对覆盖，来源等权而不是把层、token、六步当独立图像。V 主要检验上下文对 A 输出的影响，U 校正检验 inactive 输出；不能将二者的降幅加成“误差原因占比”。oracle-V 仍沿 dense 自身层内 hidden 产生参考，不等于排除了 Key 与 hidden drift 的唯一因果真值。

V 路线的机制门：oracle-V 对 A SSE 的来源平均相对降幅≥10%、至少3/4源改善；learned-V 对 A SSE 平均降幅≥5%、至少3/4源改善。若 oracle-V 有用而 learned-V 无用，标为校准表达/统计不足并 Revise；若 oracle-V 也无用，停止继续扩大 Value 表，转向单独登记的 joint-KV/核心上下文诊断。U 路线保留前述留一门，并要求本组同状态 inactive SSE 平均不增、至少3/4源改善。任一路径损害活动输出/原始状态合同都立即停止。

### 4.3 最多三个终图候选：192 DiT

只评估已经通过各自机制门的 `V_NEW8`、`U_NEW8`；两者均通过才增加 `V+U`。每候选 8 源×8步，三候选最多 24 请求、192 DiT。生成过程走各自轨迹，没有在线教师。与原 FRONT 比较固定全图 LPIPS、公共 R0/band2、额外 far 背景及整图语义。

候选继续门沿用本轮标准：至少6/8源 LPIPS下降≥10⁻⁴，配对中位数<0，严格数值通过数不降，band2 平均差≤0、extraBG 平均差≤0，且无新增明显语义错误/接缝。绝对数值门仍为 LPIPS/F≤0.02 且 extraBG≤1/255，不放宽。所有候选失败则停在本级，不再花新 Train24/Dev16 查询。即使通过，这也只是训练内筛查。

若多候选通过，仅按冻结训练平均终奖选一个主候选，平局先选额外部署操作更少者，再按固定 `U、V、V+U` 次序；不得看新 Dev16 再换候选。终奖仍使用本轮同一公式，不能把降低奖励损失等同指令正确。

## 6 结构完整核心的严格同 token、同时程对照

本实验不再把随机 SHA 分组称为结构闭合。只根据源图与提示，在查看新模型输出前标注被编辑对象及直接接触/支撑对象的可见完整区域；手、头发、容器、盘内物体、酒杯等是否属于支持结构需逐例记录理由。人工先验只诊断“完整支持区域是否有用”，不证明已提出自动识别算法。

令 `H=原R2∪完整支持对象token集`、`K=|H|`。两臂均保留原 R2：

- `CLOSE_K`：核心为 H，确保已标注支持对象完整覆盖；
- `GEO_K`：从原 R2 按冻结的距离、坐标次序作普通扩展，恰好达到 K，不使用接触对象标注。

每臂用自己的核心重新划分 E 与四等组，保持 K、r、q 相同；两臂都使用 FRONT。因此各个步骤选中目标数和总量 `2N+6(K+r)+6q` 完全一致，条件图/text始终更新。比较的只有所选几何及其后续轨迹，校准统一关闭为 identity，排除校准器在不同几何上的覆盖变化。相对原 FRONT 的计算增加另列，不能称 CLOSE_K 与原 R2 同预算。

拟冻结可行上限 `K/N≤0.5`；对象无法明确闭合、闭合范围超限或普通扩展无法满足严格等额时，两臂都走预登记 full fallback，并记录原因、8个真实前向、目标 token 和延迟，不裁掉对象来假装闭合成功。K=原R2大小等退化同选区情况保留，标记无几何对比信息，不能当独立改善。有效几何对不足8/16源时只作可行性报告，不宣布结构优越。

结构继续门针对有效的 m 个同预算配对：至少 `ceil(0.75m)` 源 LPIPS/F 下降≥10⁻⁴，配对中位数<0，严格通过数不降、公共 band2 与 extraBG 平均差≤0、无新增明显语义或全图接缝。含 full fallback 的全部16源结果、可行率和时间也必须披露；不能只报告可行子集或将两臂共同回退算成结构算法成功。

## 7 新 Dev16：一次冻结五配置，语义与全图检查是硬门

五配置固定为 `F / FRONT_ID / CORR_FRONT32 / GEO_K / CLOSE_K`，每源各一次，共80请求640DiT。CORR_FRONT32 只使用 Train8 选定算法类别及 Train32 系数；GEO/CLOSE 均为 identity。F、输入、生成 latent、scheduler、分辨率、CFG、LoRA及质量工具与当前主线合同一致，先冻结 ROI/几何、表、代码、配置顺序与所有阈值再生成。每源仅一次的时延只作描述，不能直接构造稳定节时结论。

CORR_FRONT32 的主要继续比较是对 FRONT_ID：至少12/16源 LPIPS下降≥10⁻⁴、配对中位数<0、严格通过数不降、公共 band2 与 extraBG 平均差≤0、无新增明确语义失败。来源等权，缺失/失败不算通过。结构臂单独按上一节判门，不把两条路线任一胜出当作另一条成立。

逐源必须同时查看源图、F、候选的**整图**与固定核心/边界裁剪，并叠加实际计算区。随机隐藏配置标签进行配对审核，保留显示顺序及判断记录；人工构造 ROI 的知情性仍如实披露。至少分别填写指令达成、文字/数量/实体、背景保持、接触关系、计算区色块/矩形框/接缝、F既有错误和候选新增错误。特别要求查找类似酒杯粉色边框的域外伪影，不能用低核心LPIPS抵消它。语义未审完即为 pending，不能填零错误。

上述继续门只决定是否值得进一步研究。若要称本级工程质量通过，还要求16/16源满足绝对数值门且语义无新增明显失败；任何个案失败都披露，不能称无损、正式非劣或泛化成立。F本身指令失败的来源保留并单列，不用F一致性冒充语义真值。Test仍不开封，不把Dev表现反馈到本级重训。

## 10 什么时候才重新考虑RL与系统迁移

只有固定 FRONT 加简单校准/结构规则在新来源形成可重复的质量—成本收益后，才登记下一轮策略问题。先检查不同来源或步骤是否确实需要不同动作；如果所有最优训练策略仍是同一FRONT，优先保留该规则，不为了使用RL增加actor开销。

重新训练RL前要冻结校准器、几何及可行动作库，重新检查新动作实际产生的anchor pair覆盖。训练标签仅来自Train32当前学生状态，不能拿Dev教师误差作状态/奖励；要有同增量数据与优化额度的IL_PLUS、FRONT、同预算轮转和完整fallback对照。RL必须在相同全部数值及语义门下超过简单FRONT和同数据SL，并另做训练seed/新来源核验，才讨论RL新增价值。本轮动作等价与失败门不支持这种主张。

SGLang迁移也不作为修补算法失败的途径。先保留diffusers上可复现的精确执行器和负结果；只有候选质量通过、单卡净成本有收益、索引/动态shape/缓存合同稳定后，才把固定算法迁移到SGLang并分别验证数值等价与系统收益。H800仍为主线硬件；H20只作为以后另登记的硬件扩展。
