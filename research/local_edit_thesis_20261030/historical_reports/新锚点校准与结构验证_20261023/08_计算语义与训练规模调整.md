# 计算语义与训练规模调整

更新：2026-10-25。此为用户追问的代码核对与后续方案说明，新增模型调用、下载和训练均为0。原184文件暂停快照不变；本文件不是新规模实验的执行预登记。

## 非编辑区域究竟如何参与计算

当前实现没有把输出中选区外的像素直接从原图粘贴回来。目标latent整幅参与8步更新，最后整幅VAE解码；原图另以完整条件图tokens提供信息。语义上的编辑区域、扩边后的必算区域R2、本步实际重算集合S_t是不同概念。

| 对象 | 每个局部计算步的处理 |
|---|---|
| 本步选中的目标tokens | 当前latent进入各层，重新计算Q/K/V、attention输出、MLP和velocity；更新这些token的真实缓存与锚点 |
| 本步未选中的目标tokens | 跳过其当前层Q/K/V投影、attention输出行和MLP；其历史逐层K/V仍供其他queries读取，仍产生attention乘法/加权计算与内存成本 |
| 未选中目标的输出速度 | FRONT_ID复用最近一次真实计算的velocity；当前U候选对这个历史速度作按真实(t,s)索引的有界通道仿射校正 |
| 所有目标latent | 都由scheduler更新，未选中的latent也不冻结；后续重新选中时从当前latent重算 |
| 文本、完整条件图tokens | 在每次DiT中均更新；当前加速主要裁减目标图tokens，不裁减完整条件分支 |
| 最终图像 | 整幅latent解码，无原图背景硬拷贝或最终mask合成 |

当前U-only候选的inactive K/V是原始历史缓存，没有同时启用Value校正。U校正只修改返回scheduler的预测副本，不把估计写回raw K/V、raw velocity或真实更新时间。用简记表示：

\[
\widehat v_{t,i}=\begin{cases}
v^{\mathrm{local}}_{t,i},&i\in S_t,\\
a_{t,s_i}\odot v^{\mathrm{raw}}_{s_i,i}+b_{t,s_i},&i\notin S_t.
\end{cases}
\]

实际更新代码为 `(z.float() + delta_tensor * prediction).to(torch.bfloat16)`，包含已核验的零维FP32标量乘BF16预测的舍入语义。这个公式的输入是当前目标latent和预测速度，不是原图像素。

FRONT的8步按用户直观的一基编号：第1、2、8步所有目标tokens重算；第3步重算R2、固定余数及两组域外tokens；第4—7步重算R2与固定余数，其余目标tokens复用缓存。因此域外不是全程零计算，最后也经过完整计算。

注意力仍使用完整目标K/V列。局部步的query行为文本、完整条件图及本步选中目标；所以节省来自减少目标query行及其投影/MLP等，不能把目标选中比例直接解释为端到端节时比例。

代码依据：[目标执行器](../小样本校准启动_20261023/scripts/local_executor.py)、[刷新执行器](../风险约束刷新与策略学习_20261023/scripts/refresh_runtime.py)、[速度校正](scripts/velocity_affine_runtime.py)、[D2运行入口](scripts/run_d2_u.py)。本次核对源文件SHA与D2冻结合同一致，非仅按设计文档推测。

## 是否能增加训练数据和RL

可以放宽小样本规模，将“小样本”作为训练效率目标，同时报告性能—来源数—采集成本曲线。现在的证据不足以断言失败只因训练量不足：旧神经速度头Train8有7/8终图改善，Probe8只有1/8；当前闭式U有训练内小幅收益，但未证明新来源泛化。当前U由统计矩闭式拟合，多跑epoch没有意义，应先增加独立来源或修改模型与损失。

拟研究的扩量顺序为候选Train32→64→128；保持算法、每源标签量、刷新与预算合同一致，形成嵌套的来源组集合，固定开发集。任何新来源仍须排除已见Probe、开发和封存Test组，不把同一图的多个seed算作多个独立来源。32→64若训练误差下降而开发集闭环质量不改善，不默认继续128；先定位表达、状态分布或损失目标的问题。扩规模需要新预登记，不能事后改当前D0门。

RL可考虑64→256→1024个新生成episode的分档试验，但先要求执行器在新源上具备质量/成本收益、动作有可利用差异、动作产生的真实锚点被校准合同覆盖。旧PPO已经训练64episodes/64更新，部署与固定FRONT等价；这是当前未出现RL增量的证据，不是训练更久必然有效的证据。

每档RL都应比较固定FRONT、同预算轮转、训练集选出的固定策略、共享全部新增轨迹的IL_PLUS，以及等环境查询预算的搜索基线。奖励只来自训练来源，教师一致性不能冒充编辑语义真值。评价包含开发集配对终图、背景、边界、语义及包含actor/特征/索引开销的净延迟；若动作仍全部等价FRONT或只增加训练奖励，应修订问题定义而不是盲目堆轮数。

成本示例：每episode为8步时，64/256/1024总episode分别对应512/2048/8192次学生DiT，额外教师、F参考、评测、预热与失败另计。若每新增来源采8学生+6同状态教师并另生成8步F，则32→64新增标签与F需704DiT、64→128需1408DiT；这不是完整实验总预算，也不代表这些运行已经启动。

拟采用原Dev16继续标准作为参考：至少12/16来源LPIPS下降≥0.0001、配对中位数下降、严格通过数不减少、平均边界/额外背景误差不增且无新增明显语义失败。多次使用同一Dev会使它成为调优开发集，不能再当最终独立测试；方法冻结后的Test64仍单独保留。

训练校正头解决“复用时如何减少预测误差”，策略学习解决“何时、哪些区域值得真实重算”。两项贡献分别验证，不能用训练量增加代替正确机制、质量合同或实际速度收益。
