## 1. 研究问题与前级依据

本轮检验的问题是：固定真实刷新时程与 token 预算后，能否通过小样本拟合修正真实历史锚点的域外 velocity，并使一步数值收益传递到学生自身闭环终图？D0、D1、D2 分别回答拟合关系、同状态作用位置和闭环传播三个问题，不能以其中一环替代另外两环。

D0 已用旧 Train8 的同状态教师标签分别拟合 V 与 U。两路均选择 η=0.01，但冻结的来源等权留一归一化 SSE 降幅为 V 9.383676%、U 18.548673%，且两路各 8/8 来源严格改善。V 未达到预注册 10% 门，停止该候选扩展；仅 U 进入 D1/D2。不能因为 V 接近门槛而事后下调阈值，也不能把省下的 V 影子前向额度转作额外调参。

## 2. 方法、执行语义与公平比较

### 2.1 真实锚点与校准对象

记第 t 步输入 latent 为 z_t，当前实际重算 token 集合为 S_t，其补集为 U_t。token i 最近一次真实网络计算的步号为 s_i，缓存年龄是 t−s_i。拟合表按真实步号对 (t,s_i) 读取，不能把年龄直接当作 s 轴，也不能因为预测了一个值便把缓存年龄清零。

本次 FRONT 六个中间步动作固定为 `[15,3,0,0,0,0]`。采用零基步号：第 0、1、7 步完整目标计算；第 2 步计算原 R2、固定余数及第 0/1 组；第 3–6 步只计算原 R2 和固定余数。每源分区、组大小、实际选择数量与旧 FRONT 相同。观察到的九种 stale 配对为 (2,1)、(3…6,1)、(3…6,2)。

对 packed velocity 的每个通道 c，以真实历史速度 x=v^raw_{s_i,i,c} 为输入，拟合当前同状态 dense 目标 y=v*_{t,i,c}：

\[
\widehat y=a_{t,s_i,c}x+b_{t,s_i,c}.
\]

同一配对内先将各来源原始矩除以本来源样本数，再对来源等权合并。identity prior ridge 的解与约束为：

\[
\lambda=\eta\,\operatorname{mean}_{c}\operatorname{var}(x)+10^{-12},\quad
 a_{raw}=\frac{\operatorname{cov}(x,y)+\lambda}{\operatorname{var}(x)+\lambda},\quad
 b_{raw}=\mu_y-a_{raw}\mu_x,
\]

\[
 a=\operatorname{clip}(a_{raw},0.5,1.5),\qquad
 b=\operatorname{clip}(b_{raw},-B_c,B_c),\qquad
 B_c=0.25\sqrt{E[y_c^2]}+10^{-6}.
\]

a_raw、b_raw 独立裁剪；裁剪 a 后不重算 b。D0 留一选择中的 λ、RMS 界均由其余七源计算。D1/D2 使用随后由全部 Train8 拟合的最终表，**并非逐源使用留一表**。U 有 9×64×2=1152 个有效系数；完整 8×8×64 的 FP32 a/b 表占 32768 字节，另有 coverage 与元数据。表小不等于部署附加开销已经测得。

### 2.2 返回值校准与缓存不可污染

在当前真实学生预测上先 clone 返回张量，校准仅作用于 U_t：

\[
\widetilde v_{t,i}=\begin{cases}
 v^{local}_{t,i},&i\in S_t,\\
 \operatorname{BF16}\!\left[a_{t,s_i}\odot\operatorname{FP32}(v^{raw}_{s_i,i})+b_{t,s_i}\right],&i\in U_t.
\end{cases}
\]

真实 raw K/V、raw velocity、age 和条件图输出不被仿射回写。当前同状态的活动输出保持逐位不变；D2 下一步 latent 已改变后，活动输出自然可能改变，这属于闭环传播。未知或同时间配对的 API 默认为 identity；本轮所有实际 stale 读取都必须被拟合 coverage 覆盖，出现真实 fallback 就停止，而非悄悄回退后声称模型起效。

真实 scheduler 更新按已验证的零维 FP32 delta Tensor 执行：

\[
 z_{t+1}=\operatorname{BF16}\!\left(\operatorname{FP32}(z_t)+\Delta\sigma_t\,\widetilde v_t\right).
\]

上式为更新关系的简记；实际逐位合同是 `(z.float() + delta_tensor * prediction).to(torch.bfloat16)`，其中delta_tensor为零维FP32、prediction为BF16。PyTorch的零维标量提升规则使乘积保留BF16舍入，再与FP32状态相加，因此不能把简式解释为全FP32乘法后只在末尾舍入。BF16舍入与逐位一致性是验收对象。未来训练可对FP32连续代理反传，但不能宣称对真实舍入算子做了等价可微优化。

## 3. D1：同状态机制结果与两类 SSE 聚合

### 3.1 指标定义与预注册门

对于来源 j 的六个中间状态，记未校准 inactive SSE 为 E⁰_j、U 校准后为 Eᵁ_j：

\[
 E^m_j=\sum_{t=1}^{6}\sum_{i\in U_t,c}
 \left(v^m_{j,t,i,c}-v^*_{j,t,i,c}\right)^2.
\]

第 1 中间步没有 inactive，空集贡献为零，但 dense 完整路径控制仍真实调用并计费。本次冻结门同时要求：原始 SSE 来源均值不增加、每源相对降幅的均值不为负、至少 3/4 来源严格改善，以及全部执行合同通过。

两种降幅必须区分：

\[
 G_{sum}=1-\frac{\frac14\sum_j E^U_j}{\frac14\sum_j E^0_j}
 =12.353247\%,
\qquad
 G_{relative}=\frac14\sum_j\left(1-\frac{E^U_j}{E^0_j+10^{-12}}\right)
 =32.137022\%.
\]

前者由原始 SSE 均值之比得到；虽然先对来源取均值，但计算相对降幅时，原误差大的来源影响更大。后者先计算每源相对改善，再给每个来源相同权重，低原误差来源与高原误差来源各占四分之一。两者并不矛盾，不能把 32.137022% 写成总体原始 SSE 减少了三分之一。

D0 使用的 teacher-energy 归一化又是第三种量：R_j=E_j/(Y_j+10⁻¹²)，Y_j 为相同采样集合的教师平方和。D1 附加统计中，mean(R⁰)=0.007083449708，mean(Rᵁ)=0.006233117570，其均值之比下降 12.004492%。该数字可辅助解释，**不替换已冻结 D1 门，也不直接与 D0 留一降幅等同**；D1 使用全部八源拟合后的模型并包含真实 BF16 部署。

## 4. D2：训练内自身轨迹终图

### 4.1 指标、固定区域与旧参考复用

每源新生成一张 U_FRONT_OWN 图，共 8 请求、64 次学生 DiT、0 dense。旧 F 和 FRONT 各八张原图按 SHA 复用，不为本轮重新生成。LPIPS 使用冻结的 AlexNet spatial map mean 与 normalize=True；输入 RGB 为 [0,1]。旧 F/FRONT 的七项已存指标重新计算，允许差为 10⁻⁶，实测最大绝对差为 0。运行时核对实际权重路径与哈希并禁止权重下载；本机独立审计只核对保存的权重摘要和来源，并未在本机重新运行 LPIPS。

R0 为原 mask bbox 向外取整到 16 像素 packed token；band2 为 D₂(R0)∩D₂(¬R0)，同时包含边界内外；far 为冻结 R2 的补集。每个方法使用同一组公共掩码。图中 band2-context 裁剪是包含该环带及其包围核心的矩形，不能把整个裁剪框都称为数值 band2。

额外背景误差采用有符号差：

\[
 B(I)=\operatorname{MAE}_{far}(I,I_{src})-
 \operatorname{MAE}_{far}(I_F,I_{src}).
\]

B<0 仅表示该候选在该区域的平均像素变化小于 F，并不说明背景完全未改、语义正确或编辑成功；错误保留本该编辑的区域也可能降低该量。尤其 ROI 错位时，far 可能包含实际编辑对象。

单源严格数值门为 LPIPS/F≤0.02 且 B≤1/255。F 对自身 LPIPS=0、B=0，故其 8/8 数值通过是定义结果，不能当作教师语义正确率。

## 7. 当前可以成立的研究判断

第一，训练确实可以修正一部分局部执行误差：U 表来自八来源同状态数据，能够以真实锚点索引在运行时部署，且对训练内完整终图出现小幅一致 LPIPS/F 改善。与旧 29,696 参数神经 velocity 头在 Probe8 的 1 好 7 坏相比，当前观察说明值得认真检查状态与参数化的匹配；它不构成两个模型在相同数据、基底和独立测试上的公平胜负。

第二，不能把“误差完全消除”作为当前结论。D1 保留活动误差和 inactive 残差，D2 仍有 2/8 严格数值不通过及逐源指标退化，共同语义问题也未修复。仿射模型缺少内容与空间耦合信息，可能只能补偿可预测的平均偏移；这一解释仍需有控制的后续消融，不能由当前相关性确定失败原因。

第三，关于用户提出的“适当扩到周围、使边界更完整”的想法，本轮结果提供了继续验证的动机：bbox/R2 与实际编辑对象错位、邻接非目标对象被共同修改，说明只看变化 bbox 或区域均值不充分。然而本轮选区完全固定，没有比较结构选区；**结构完整扩边的效果尚未成立**。增加面积本身可能改善质量，必须以严格相同 token 预算分离“选得更好”和“算得更多”。

第四，RL 的必要性尚未成立。此前真实训练的 PPO 在 Probe8 确定性输出与 STATIC/IL 等价，不能把固定 FRONT 的性能当作策略增量。本轮只拟合 U 表，没有更新刷新策略。现在最直接的工作是独立来源复验和质量风险边界，不能先扩大 RL 再寻找有利解释。

## 8. 后续实验路径与进入条件（均为计划）

### 8.1 新来源扩展：NewTrain24 与 Train32

沿用已冻结的 [future_source_plan.json](../风险约束刷新与策略学习_20261023/data/future_source_plan.json)：原始 COCO img_id 为分组单位，保留官方分区及 hash 排名。旧 Probe8 实际占原 train rank 9–16，不能误当全新训练来源；NewTrain24 取之后未见 train rank 17–40，Train32=原 Train8+NewTrain24。新 Dev16 来自未见官方 dev rank 17–32；旧 Val16、Probe8 与封存 Test64 不进入新训练或新 Dev。

联合门现已允许推进来源媒体 QC；只有 QC 与实现预注册通过后，才执行 D3 的 NewTrain24 完整 F（192 DiT 条件预算）和 D4 的 FRONT 同状态标签（336 DiT 条件预算）。本报告未执行这两项。QC 依据源图、指令、原标注合法性及提前规定的可判定条件，不依据新候选生成质量挑简单图；拒收须保留原因并按已冻结规则处理，不静默替换。拟合、阈值和唯一模型类别在打开 Dev16 质量前冻结。若要做 Train8→16→24→32 的来源规模曲线，应预先规定嵌套集合与各自拟合规则，不能在 Dev 上选择最好规模后仍称 Dev 未参与选择。

### 8.2 Dev16：泛化与同 token 结构选区

至少保留完整 F、原 FRONT identity、同 FRONT 的 U 校准三类基线，以分离真实刷新和 U 校准贡献。结构选区比较必须使用同一模型、校准、时程、初始噪声和每步目标 token 数；普通扩张与结构完整选区各自由源图/提示词/冻结预处理产生，在看到候选终图前保存 indices、算法参数、随机种子与 SHA。

对每源每步规定预算 K_{j,t}，满足：

\[
 |S^{ordinary}_{j,t}|=|S^{structure}_{j,t}|=K_{j,t}.
\]

同样固定 full steps、条件 token、文本、真实刷新组预算和请求级总 token 量。结构选区应优先包含目标、接触关系和必要边界，但不能读取完整当前教师隐藏、未来帧或终图变化来选区。若必需结构在固定预算内无法容纳，按预注册的不可行/回退规则记账，不偷偷扩大预算；更高预算作为独立轴另报。区域构建和分割成本也必须计入端到端延迟。

同预算对照同时报告公共评估区域及源图/指令整图语义，不让方法自定义掩码成为自身评分优势。冰箱 ROI 错位与鸟/酒杯非目标修改可用于训练阶段完善规则，但不能为未来 Dev 逐图人工挑选最有利选区。当前没有执行这项结构对照。

### 8.3 延迟：必须通过质量后独立测量

冻结唯一候选并通过未见来源质量后，另立关闭诊断断言/缓存快照的部署计时协议。包括同步后的预热、多次交错配对、相同输入与分辨率、相同模型驻留及温度/并发条件，报告逐来源中位端到端延迟、执行器部分、额外头/选区成本、波动与显存。F、FRONT、U 及结构候选都执行同等测量规则。

模型加载时间是否单列必须提前说明；区域解析、clone/gather/affine/cast 不能被排除在部署净收益之外。当前单次 audit=True 日志包含摘要、完整状态核查等开销，不与历史不同模式的 FRONT/F 耗时作净加速比。尚未通过质量的分支不消耗为“证明加速”预留的计时额度。

### 8.4 更强小头与约束 RL 的条件

仅在新来源上确认有益且识别残余误差后，才比较有界仿射与一个冻结的轻量空间残差头。训练数据、教师标签、采样状态和基底执行器必须相同；记录同状态与自身轨迹分布差，不再只用离线训练损失替代闭环验收。未来可用速度、时间加权一步代理及边界梯度联合损失，但应明确：

\[
 L_v=\frac{\|\widehat v-v^*\|_{U}^{2}}{\|v^*\|_{U}^{2}+\epsilon},\qquad
 L_{step}^{FP32}=\|\Delta\sigma_t(\widehat v-v^*)\|_{U}^{2},\qquad
 L_{edge}=\|\nabla\widehat v-\nabla v^*\|_{\partial S}.
\]

同状态、同 Δσ 下 L_step 只提供时间权重，不是独立教师信息；不要再次全量归一化而抵消 Δσ²。边界梯度增加空间耦合，可通过“仅速度 / 速度加时间权重 / 速度加边界”冻结消融检验。FP32 代理用于反传，真实 BF16 scheduler 用于验收。不能只因可设计联合损失就预告可消除误差。

只有固定规则、强监督调度基线与 U/结构路线在新 Dev 上稳定、且内容相关动作差异具有可利用收益时，才进入约束策略学习。可写成最小化部署成本、满足质量风险与预算约束的目标：

\[
 \min_\pi E[C(\pi)]\quad
 \text{s.t.}\ E[R_{quality}(\pi)]\le\tau_q,\quad
 P(\text{明显语义失败})\le\tau_s,\quad
 \sum_t |S_t|\le K.
\]

阈值必须在训练/开发协议中冻结，不能用 Dev 或 Test 结果反向挑选。部署状态只读取当前可得的源图语义、已算 token 摘要、真实 age、剩余预算等；教师结果可用于训练 reward，但教师前向和额外 rollout 全部计入训练预算，不进入部署策略输入。

PPO、IL、规则 FRONT/ROTATION 等应共享相同来源和可得轨迹标签，RL 额外查询要有同数据的 IL_PLUS 或等计算预算对照。固定确定性评估、多个训练随机种子和动作/PNG 等价审计；若 PPO 又退化为固定 FRONT 或未超过强监督/规则基线，就报告无策略增量并停止扩大。Test64 保持封存至模型、阈值、选区、预算与最终评估协议全部锁定后使用。
