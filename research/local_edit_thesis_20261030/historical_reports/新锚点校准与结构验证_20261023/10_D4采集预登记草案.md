# D4：新训练来源 U-only 同状态采集与原始监督存档草案

状态：**实现与执行前审查草案，未执行、未批准模型运行**。本文件不替代代码冻结、CPU 合同回执、D3 独立审计或根任务的 D4 执行决定。旧 D0、D1、D2、来源提取及标注文件均不修改。

## 1. 本轮目标与保持不变的部分

沿已冻结 NewTrain24 的原始顺序采集 `FRONT_ID` 自身轨迹。局部来源使用原始 R2、原 SHA 分组及中间六步 `[15,3,0,0,0,0]`；不把结构对照的 CLOSE_K/GEO_K 核心混入这次校准。每个中间状态的教师接收学生当下完全相同的输入，不独立推进 scheduler。

本轮只形成 U velocity 的充分统计量，停止的 Value 路线不恢复。固定本阶段已经选定的 **η=0.01**，保持 identity prior ridge、来源等权、原 a/b 独立限幅顺序及同时间/未覆盖配对 identity 规则。不重新扫描 η，不用 Dev/Probe/Test 选择系数。本采集入口不进行拟合；后续拟合必须独立冻结并接受验收。

旧 D0 的 η 候选集合与留一选择历史保持原样；这里固定的是旧 Train8 已选出的值。不能把“固定旧结果”写成 D0 从未搜索参数。

## 3. 复用接口与正确性边界

新增 `d4_u_archive.py` 的 `UArchiveCollector` 继承冻结 `AnchorCollector`，复用原学生前向、同状态教师、完整状态审计、真实锚点 U 统计及 BF16 Euler 核验。Value hook 只见证教师层到达，不累计 Value 标签；原 KV 指针、版本及分层抽样内容检查保留，其费用属于诊断成本。

新增存档观察器仅复制数据，不替换模型返回值，不修改 raw K/V、raw velocity、年龄、锚点、刷新选择或随机状态。归档时机明确为：

1. 学生已完成本步真实刷新，scheduler 尚未更新；取得当前 `z_t`、完整返回的原始 velocity、真实 anchor latent/velocity/age 与选区。
2. k=1…6 的同一次既有 dense 调用返回同状态教师 velocity；不额外运行教师，不替换学生预测。
3. 原 collector 的教师隔离检查通过，原学生预测正常返回 pipeline。
4. 实际 `callback_on_step_end` 提供更新后的 latent，先通过原 bitwise Euler 检查，随后才把该状态及 `actual_post_latent` 写入不可覆盖文件。

因此活动 token 的 anchor 是本步 k，inactive token 的 anchor 仍是其最后一次真实重算的 s；不能把“存档后复制的时间”当成新鲜锚点。

## 4. 原始监督存档

每个局部来源保留 8 步轨迹。中间六步额外保留原始监督数组，其中 k=1 的 inactive 集为空，是控制状态；有 U 训练标签的状态为 k=2…6。端点仅保存轨迹，不添加未实际调用的 teacher 字段。全图回退只存 8 步轨迹，不复制无意义 anchor/teacher 训练数据。

| 数组或元数据 | 形状/含义 |
|---|---|
| `z_current`、`raw_velocity`、`actual_post_latent` | `[1,N,C]`，完整目标 packed latent/预测，真实 C=64 |
| `teacher_velocity` | 仅真实 dense 调用的中间步存在，`[1,N,C]` |
| `anchor_latent`、`anchor_velocity` | 中间步真实缓存，`[1,N,C]`；不以当前估计替代 |
| `age` | `[N]`，原始最后刷新步 s；另可由 k−s 计算 stale age |
| `selected_indices`、`selected_mask`、`inactive_mask` | 原目标坐标；inactive 与 selected 严格互补 |
| `sigma`、`delta_sigma`、模型 timestep | FP32 sigma/dt 及真实 timestep 表达，记录实际算术 dtype |
| 静态 mask | 原目标分辨率 binary mask、R0/R2/band2 token mask、有效相邻边定义 |
| 来源与几何 | source/mask/partition/protocol SHA、prompt、grid、packed patch=2 与通道布局 |

BF16 数组按 uint16 原始位存储，显式注明原 dtype/shape/字节 SHA；读取时必须按 bit pattern 恢复，不能把 uint16 数值当预测值。FP32 CPU 检查按其原始位保存。每状态 NPZ 与 JSON 侧车均不可覆盖，并保存实际字节大小、逐数组 SHA 和文件 SHA。JSON 的 `teacher_available`、`inactive_supervision_available` 必须与数组存在性及 U token 数一致。

旧八个来源只有原 D0 moments，没有此次逐 token 原始数组。因此 **31 源 U 表拟合候选** 与 **23 源新原始残差监督档案** 必须分开报告；原始数组不足不能用再次运行旧八源而不记费用的方式补齐。

## 5. 能支持的后续损失与不能作出的结论

对记录状态的 U 集，未来可计算

\[
\mathcal L_v=\frac{1}{|U|C}\sum_{i\in U}\left\|v_i^{\rm raw}+r_\theta(x_i)-v_i^{\rm dense}(z_t)\right\|_2^2.
\]

`x_i` 可使用当时可部署获取的当前/锚点 latent、raw velocity、真实 age、sigma 和 mask，不能偷用教师 velocity、未来 actual_post 或任何官方 target 作为部署输入。教师及实际下一步 latent 是监督/验收数据，是否纳入训练目标需另行预登记。

在固定当前 `z_t` 上，可以由相同 dt 建立局部一步目标与边界差分损失。若采用 FP32 可微代理，应明确这是代理；部署按 BF16 实际乘法/舍入更新，需另测误差。保存的实际 callback latent用于重放验收，不等价于能离线反向传播完整 8 步扩散轨迹。将 packed channel 解包至原 latent 空间再取空间梯度时，必须使用冻结的 patch=2 通道排列，不能把64个packed通道误当相邻空间位置。

存档中的 `band2_token_mask` 和 `band2_neighbor_edges` 是 R0 矩形 token bbox 向内/外各两格形成的带及其相邻边，属于 latent/token 空间诊断代理；它们**不等于既有终图像素质量评估的 band2**。后续终图质量仍须使用原冻结 mask 与原固定 quality metric，不用这套 token 边代替、重新定义或选择像素 band2 指标。

这些数据不能直接证明 richer head 有效、策略可学或 RL 能改善终图；它们仍来自固定 FRONT_ID 的训练来源。未来头的容量、输入、损失、闭环补采、优化步数、独立验证与 RL 查询预算须另建协议，本轮不训练也不选 richer head。

## 6. 存储与时间

在本批 1024² 输出、N=4096、C=64、BF16 下，一个完整目标数组约0.5 MiB。局部来源8步三项轨迹数组约12 MiB，中间六步三项 teacher/anchor 数组另9 MiB，约21 MiB/源；23源约483 MiB。全图来源8步三项轨迹约12 MiB，24张原分辨率binary mask约24 MiB，另加年龄、索引、布尔mask、NPZ/JSON和U moments，预计约 **0.55–0.65 GiB**。最终以实际文件字节为准，空间检查至少保留2 GiB余量；CPU状态逐步写盘，避免累积整批GPU张量。

计时包含教师、审计、CPU复制、NPZ序列化、哈希和实际文件写入；这不是部署净延迟。存档开销新增0 DiT，但不等于零墙钟、零显存或零磁盘成本。

## 7. 执行前验收与停止条件

要求 D3 全24源/192调用完成、独立执行审计通过，源QC与结构冻结链有效；D4复用D3保存的对应源latent，模型/LoRA/seed/CFG/分辨率/timestep/sigma与D3一致。独立D4代码审阅必须绑定最终源码与CPU回执SHA，并明确 `ready_for_D4_U=true`，否则入口不得加载模型。

新 helper 与 runner 均在 k=1 返回前硬断言 `full_target_control_prediction_bitwise_equal is True` 且 `full_target_control_prediction_max_abs == 0`，任何失配立即停止；helper 在归档该步前即拒绝，旧父模块保持不变。

CPU tiny 至少覆盖 FP32/BF16：新归档collector与旧collector的8步输出/缓存/年龄/实际Euler一致；U moments逐项相同；6次同状态teacher严格同输入；存档读回位相同且真实anchor正确；k=1 U为空、端点teacher缺席；native全图分支8步与独立native参考一致且0教师/0U moments；已有文件、错误state/shape/hash拒绝，异常不自动重试。CPU tiny另显式断言 k=1 两项精确控制，并用不增加前向的故障注入分别验证 false flag 与非零 max_abs 均被新 helper 拒绝。CPU tiny不计真实Qwen模型DiT，也不能冒充真实D4通过。

正式运行逐调用记录invoked/completed，首个失败即停并保存部分NPZ/JSON、PNG、ledger与status。禁止自动重跑、换源、恢复半条轨迹或删除失败成本。成功仅说明采集合同成立；拟合、D5、Dev、RL均不自动启动。

## 8. 新实现、CPU 检查与执行入口

仅新增 `scripts/d4_u_archive.py` 与 `scripts/run_d4_u.py`。旧 `AnchorCollector`、刷新执行器、拟合器和 D0/D1/D2 文件不修改。CPU 自检位于 helper 内，不导入真实权重；每个 dtype 的前向数为旧 local collector 14、新归档 local collector 14、独立 native 8、归档 native 8，FP32/BF16 合计 **88 次 tiny 前向、0 次真实模型 DiT**。其实际 PASS 回执尚待运行，静态编译检查不等于 CPU PASS。

```bash
python scripts/d4_u_archive.py --self-test --output data/check_d4_u_archive.json
```

`run_d4_u.py` 的六项显式输入为 `--cases`、`--source-qc`、`--geometry-freeze`、`--d3-audit`、`--review`、`--cpu-receipt`。`--preflight-only` 仅校验冻结文件、来源与回执，不导入模型；缺失实际 D3 收据或 D4 readiness 时会拒绝，不能预造 PASS。

D3 独立审计须提供 `status=PASS`、`protocol_sha256`、`ledger_sha256`、`status_sha256`、`cases_sha256`、24 来源原顺序和 192 次 invoked/completed，以及调用完整、Euler/哈希、source/latent、输出可解码、冻结输入未变的明确检查。该审计只证明 F 参考工程有效，不证明编辑语义正确。

D4 独立审阅须绑定 `execution_source_sha256`、`cpu_receipt_sha256`、`d3_audit_sha256` 并明确 `ready_for_D4_U=true`。真实入口在载入模型前生成 `data_d4_u/preregistration.json` 和 `sampling_plan.json`，第一次调用之前冻结所有计划；新建目录已有任意旧尝试即停止。

预计输出：`data_d4_u/runs.jsonl` 24 条成功请求，`steps.jsonl` 192 条实际 callback，`calls.jsonl` 660 条 invoked/completed 事件，23 份 U moments，`outputs_d4_u/` 24 个 PNG。`raw_d4_u/` 每源一份静态 mask 几何 NPZ 及 8 份状态 NPZ，均有不可覆盖 JSON 侧车；共 192 个轨迹状态，其中 138 个具有真实 dense 字段、115 个具有非空 U 标签。全图回退的 8 步都没有 teacher 字段。按实际 stage/源/状态记录文件 SHA 和字节数。
