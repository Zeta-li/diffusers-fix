# 优化数据摘要

阶段：`optimization`；数据汇总状态：**complete**。三个已查看的演示输入，每配置 3 次计时，质量仅取 repeat0。complete仅表示数据汇总齐备，不代表所有验收通过。

实际交错：先完成全部case/config预热，再按repeat外循环、源cases.json中的case顺序内循环，配置循环位移为 `(repeat+case_index)%配置数`；同case/repeat配对F。该描述核对实际runner，不修改已冻结的主协议。

完成 48/48 条相关请求，记录 384/384 次 DiT。预热、失败和重复成功记录分别统计，原始失败行不删除。

## 2 输出值调制候选

SHIFT/AFFINE 与同轮 F/R2 比较，调制成本已在请求计时内。它们不是 ROT 的同背景查询预算对照，本阶段不与 primary 的三次重复混算。是否具备质量收益需结合完整结果和单独视觉检查。

## 3 一致性与结论边界

| 输入 | 配置 | 旧基线SHA一致 | RGB一致 |
|---|---|---|---|
| blocks_text | F | 是 | 是 |
| blocks_text | R2 | 是 | 是 |
| shirt_color | F | 是 | 是 |
| shirt_color | R2 | 是 | 是 |
| remove_hair | F | 是 | 是 |
| remove_hair | R2 | 是 | 是 |

所有计时重复的输出 SHA 一致：**是**；运行时选区/读缓存年龄与冻结计划一致：**是**；预热及测量完整交错顺序一致：**是**。

正式工程目标是质量过门并相对 F 净延迟下降≥10%；三案例探索不建立正式 Go。若仅有0–10%正收益，记为未达目标/Revise。没有执行显著性检验、置信区间或非劣性论证；后续必须使用隔离 Train/Val，Test 继续封存。
