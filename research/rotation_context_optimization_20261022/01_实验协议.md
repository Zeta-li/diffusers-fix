# 背景轮转刷新与上下文优化：执行前协议

日期：2026-10-22（Asia/Shanghai）。**本轮方案与预算先冻结，全部效果待测。** 本文不预判轮转刷新能恢复质量或达到加速目标。主性能不使用dense oracle，不训练模型。

## 1 问题与假设

上一轮同状态归因发现，三个开发样例中活动目标区承担约82%–92%的预测平方误差；用完整oracle替换活动输出后终图明显改善。该结果支持优先处理活动分支的旧上下文传播，但没有把纯K/V算子的因果作用单独隔离，更没有证明存在廉价可部署校正。

本轮假设：保留旧R2核心每步计算，并以有界年龄轮转刷新域外背景，可能比相同每步预算下始终计算固定一组背景更好地保留活动编辑。刷新同时更新背景K/V和最终velocity，是联合上下文/预测更新策略，不能称为“只修KV”的实验。

三个样例、一个生成seed、各配置三次计时均为工程探索。样例已多次用于机制分析，不是独立Test；本轮不能支持泛化、无损、正式成功率或统计显著性声明。

## 3 背景分组与模式

将目标token全集记为U，旧R2记为C，背景为B=U\C。设`|B|=3q+r`，`r∈{0,1,2}`。固定抽出r个背景token为共同always-fresh余数E，其余背景分为互斥、等大小的G0/G1/G2，每组q个。C、E、三组必须无重叠并恰好覆盖U。

背景按2×2目标token块组织，块顺序由冻结seed、case及块坐标的SHA256确定，块内按行列顺序。提取E与等量切分可能拆开少量块，清单必须记录拆块；不能把实际分散的组合称为一个连续背景块。分组脚本、seed、具体indices与清单hash全部冻结。

| 配置 | 第2–7步活动目标集合 | 用途 |
|---|---|---|
| F | 每步U，原生路径 | 同期完整参照 |
| R2 | 旧C | 同期原局部执行器，复现速度/质量风险 |
| FIX0 | C∪E∪G0，六步均不变 | 固定额外背景对照0 |
| FIX1 | C∪E∪G1，六步均不变 | 固定额外背景对照1 |
| FIX2 | C∪E∪G2，六步均不变 | 固定额外背景对照2 |
| ROT | 依次C∪E∪G0/G1/G2/G0/G1/G2 | 每组三步内刷新一次，六局部步覆盖两轮 |

FIX0/1/2与ROT的每个局部步都恰好计算`|C|+r+q`个目标token，真实Q/K/V新投影、MLP输入预算逐步相同；R2是低预算基线，不与ROT冒称等面积。F是完整预算。

按旧区域的计划数，文字C=1088、U=4056，E=1、q=989，扩展后2078个目标；衬衫C=1282、U=4056，E=2、q=924，扩展后2208；去发C=438、U=4096，E=1、q=1219，扩展后1658。实际执行前由清单独立复核，不能只相信这张预算表。

## 4 “年龄有界”的精确定义

每层目标缓存记录其最后真实计算的step。当前step先计算活动位置并写入新K/V，然后attention读取完整K/V；年龄为“当前step减最后刷新step”，当步新值年龄0。ROT在第2–7步的attention读取时，全部目标缓存年龄应≤2步；第1/8步全量后为0。第4/7步即将刷新的那组在写入前可能已满3步，不能把pre-update年龄错误当作违反读取上限。

E与C始终新算；三组各在两个局部步更新，另有首尾全量更新。FIX中只有所选组每步更新，另两组会更陈旧。这是预算相同但覆盖和时间分布不同的策略比较，仍不等于纯年龄单变量的独立因果干预。位置、碎片化、覆盖范围也可能影响质量与执行开销。

如记录sigma-age，应使用当前与上次刷新位置对应的实际sigma差；两步年龄不代表所有去噪阶段相同的噪声距离。本轮不根据sigma-age增加新策略。

## 5 正确性先行

`scripts/check_rotation.py`先在CPU执行标准清单检查，再借用旧tiny Qwen fixture运行真实小模型动态ROT，不下载权重，不运行20B或GPU训练。

| 检查 | 要求 |
|---|---|
| 区域来源 | C索引与旧R2逐元素一致，source regions hash一致；目标网格/数量匹配 |
| 划分 | C/E/G0/G1/G2合法、互斥、覆盖全目标；E大小r，三组大小q |
| 每步预算 | F/R2/FIX/ROT八步集合与规则一致；FIX三组和ROT每个局部步完全等token数 |
| 全覆盖/两轮 | ROT六局部步每个Gi恰好被选两次，C/E每步都在 |
| 年龄 | 独立整数模拟读取时年龄；ROT最大≤2，与计划审计字段对齐 |
| 真实tiny动态路径 | FP32/BF16、非连续选区、8步Euler；img_in接收到当前latent按原索引gather的值 |
| 真实tiny缓存 | 非活动K/V与velocity保持原缓存；新位置从当前z_t计算；age与真实更新集合一致 |
| 首尾全量 | tiny第1/8步完整输出与同状态原生完整预测一致；tiny oracle控制仅用于正确性，不进入主性能 |
| 真实模型复现 | runner另核验本轮F最终输出等旧F，本轮R2等旧R2；明确按PNG和RGB分别核对 |

清单检查和tiny通过只证明实现约定，不证明生成质量。tiny真实forward数单列，不并入576次20B预算；没有通过时不解释局部速度或质量。

## 6 冻结请求矩阵与计时

**F/R2/FIX0/FIX1/FIX2/ROT ×3样例×（预热1次+正式计时3次）=72请求、576次真实DiT。** 其中18条预热、54条计时；无dense oracle sidecar，每请求8次真实forward。小模型检查、下载、指标评估、PNG写盘和模型加载另计。

各样例先对六配置预热，再按重复轮次循环轮换配置顺序，冻结基础顺序为F/R2/FIX0/FIX1/FIX2/ROT。每轮都包含同期F，配对相同case与repeat；不能挑最快一次。三轮不能完全平衡六配置顺序，保留原始执行顺序作为限制。

请求计时从内存图像/提示及已提供的冻结策略进入，至PIL输出与GPU同步、请求cache清理结束。索引到设备、缓存更新、gather/scatter和其附加开销均在内；不跨请求保留条件缓存。报告三次中位数、配对延迟比、allocated/reserved及实际cache storage，不报P95或置信区间。

ROT变化的是每步indices，FIX固定的是同一组；不能让ROT预先完成GPU索引准备、却把FIX索引准备放入计时，或反过来。当前预提供策略的离线构造成本单独登记；未来自动选区/策略网络若引入，需重新计价。

FIX三组全部报告，不在看结果后挑出最差组作为唯一对照。可列其范围、预定义三组均值/中位数，以及最优固定组；“最优”只是本轮描述性上界，不是无需额外信息即可部署的选择器。

## 7 质量与去留口径

每配置每例只评价固定repeat0的质量，另外两次同seed计时若hash相同不计为独立质量样本。主参照为同期F；D/F也不是人工编辑真值。

- 数值保留：全图LPIPS spatial map均值≤0.02，且旧far background上`MAE(候选,源图)-MAE(F,源图)`≤1/255；按每例同时满足判定。
- 语义/边界：文字短语及字序、手/发丝/衬衫接触、发丝去除与盘面亮度台阶单独非盲核验。数值通过但有错字或接缝仍判质量不足。
- 性能：保持原约10%端到端净延迟下降的工程目标，不因为预算增加而降低目标。三重复只是探索性证据，不能替代更大独立开发集。
- 解释：ROT好于同预算FIX说明该覆盖/更新策略在当前案例有价值，不证明纯cache年龄因果，不证明自动边界或小样本训练已经成立。

扩展后的目标活动比例约40.5%–54.4%，可能吞掉旧R2仅11%–15%的速度余量；只看质量改善不足以判Go。不得把ROT质量与R2速度拼接，也不得以归因阶段带oracle的耗时作为本轮部署速度。

## 8 预先声明的失败与后续方向

| 结果类型 | 可支持的下一步 | 不做的推断 |
|---|---|---|
| ROT质量与净收益均满足，且比固定组更稳 | 在10–20个新开发输入与多个分组seed复核，之后才讨论收益学习 | 三个重复使用案例不证明泛化 |
| ROT质量改善但收益<目标 | 保留负成本结果，考虑层选择/更低刷新预算的机制诊断 | 不立即增加RL或放宽原门槛 |
| ROT不优于固定组或仍错字/分块 | 回查背景覆盖与层间传播；有依据地只追加一个低成本诊断 | 不宣布有界年龄或完整对象边界整体无效 |

候选方向只作下一轮讨论，未纳入本轮GPU预算：

1. **temb显式调制校正：**Qwen的K来自当前hidden的LN、时间scale/shift、投影、QK norm与RoPE。仅修改temb可修显式调制，不能恢复旧hidden与joint attention历史。若需保存每层旧LN特征并重投影，缓存和投影成本必须列出，不能预称廉价或精确。先在同状态诊断中测恢复上限再考虑实现。
2. **layer-partial刷新：**先比较固定浅/中/深的小层块或有依据的前缀，保持层数/背景预算可比。某深层要获得真正当前的背景hidden可能依赖前面层全量传播，必须计入上游成本；从旧hidden直接重算某层不等于完整当前层刷新。

优先保留清晰、可计价的规则对照。校正、小样本训练和SGLang移植均需本轮联合质量—速度结果及新开发数据支持；本轮不启动训练或RL。
