# 局部执行器与边界扩展：前置验证协议

编制日期：2026-10-22。版本：执行前冻结方案 v1.1。**所有新实验状态均为待执行；不含本阶段实测结果。** 后续实际执行数、偏离协议与失败记录应写入独立结果文件，不回填为预注册结果。文末保留执行前矩阵调整记录。

## 1 要回答的问题

本轮只验证三个问题：①局部路径在全选时是否保持原计算的语义；②部分 token 是否真正减少昂贵算子的计算，并在完整请求中带来净收益；③在相同活动 token 预算下，扩展到接触、遮挡与结构边界是否比机械扩框更可靠。

上一轮融合版 Lightning 8 步平均约 6.74 秒，DiT 区间占约 54.1%。因此不能将 token 面积下降直接换算为端到端提速。上一轮人物样例已有背景细节漂移，本轮的首要质量参照是**同一次环境、同一融合方式的完整 Lightning 8 步输出**；50 步输出仅作辅助参照。二者均不作为人工编辑真值。

本轮不训练策略，不启动强化学习，不触碰正式 Test 划分。三个公开演示样例只支持发现明显实现错误、质量失败及是否值得扩大验证，不能支持无损、泛化或统计显著的结论。

## 2 源码事实与执行边界

审查对象为本目录 `source_audit/transformer_qwenimage.py` 与 `source_audit/pipeline_qwenimage_edit.py`，最终执行前补存文件 SHA256、Diffusers Git 提交和新执行器脚本 SHA256。

1. pipeline 每步将目标 latent 与条件图 latent 沿 token 维拼接；DiT 的 image stream 同时包含这两组 token。上轮三个样例目标/条件分别为 4056/4056、4056/4056、4096/4096，另有约 1369–1383 个文本条件 token。
2. 每个双流 block 都执行 image/text 的 QKV、joint attention、输出投影、门控残差和各自 MLP。条件图原始 latent 跨步固定，并不意味着其深层 hidden states 或 K/V 跨步固定；文本深层表示同样会与图像交互。
3. joint attention 顺序为 `[text, image]`。目标与条件的 image RoPE 来源于完整 `img_shapes`。局部 gather 必须保留原坐标对应的 RoPE，不能将局部索引重新编号成紧凑小图。
4. `zero_cond_t` 分支会依据目标/条件身份生成 `modulate_index`。即使当前 checkpoint 不启用该分支，执行器也应显式检查其值；启用时必须同步 gather 对应索引，不能以目标 gate 调制条件 token。
5. pipeline 最终仅截取目标 token 的 noise prediction 供 scheduler 更新。局部输出重建必须仍返回完整目标形状，并清楚规定非活动 token 是复用旧预测、冻结某层表示，还是由其他近似规则更新。不能把不同近似规则混在一个“局部”标签下。

**本轮冻结的最小实现：**只对目标图指定活动集合；条件图和文本每步完整重算。每层仅对选中目标 token 与全部条件 token 执行新的 Q/K/V、attention 输出投影和 image MLP；目标图非活动位置复用该层上次真正计算后的 post-RoPE K 与 V，joint attention 仍可访问全域 K/V。末端非活动位置复用上次最终 noise prediction；scheduler 对所有目标 latent 更新，不把非活动 latent 固定为源图，也不在输出图上贴回原图。新激活位置从当前 `z_t` 的 `img_in` 输出开始逐层执行；活动 token 的原始坐标、RoPE 和 scatter 位置必须一致。第 1、8 步全量刷新。该设计仍是近似计算；“全域上下文”不等于“与完整轨迹等价”。

若目标 token 数为 N、活动目标数为 A、条件数为 C、文本数为 T，则局部步预期 image Q/K/V 的新投影长度为 A+C，joint Q 为 T+A+C，joint K/V 为 T+N+C，image MLP 为 A+C。其中 N−A 个目标 K/V 来自缓存；text Q/K/V 与 MLP 均为 T。image MLP/新投影若仍是 N+C，说明对应算子尚未真正局部化。最终输出应恢复为 N 个目标预测，登记其中 A 个新预测与 N−A 个缓存预测；第1/8步全部为新预测。

如果为降低工程复杂度同时缓存条件图/文本，应另列配置，不能再把收益归因于只局部执行目标图。第一轮优先避免叠加第二种近似。

## 3 固定输入、掩码与时间调度

继续使用上一轮三个公开演示输入 `blocks_text`、`shirt_color`、`remove_hair`，复用源图哈希和显式初始 latent。保持上一轮 BF16、融合 Lightning 8 步、CFG=1、完整作者调度器、SDPA、VAE tiling、batch=1，不量化、不编译、不跨请求复用条件编码。所有配置在本轮重跑完整参照，不能以历史 6.74 秒替代配对基线。

上一轮 ROI 原先用于离线诊断。若本轮把其核心框转换为在线活动集合，必须登记为**人工预给区域的执行器实验**，不能声称已完成自动语义定位。允许变化粗框也不是像素级真值。

候选掩码只允许由源图、指令及冻结人工标注生成；禁止看完整模型的本轮输出差分后调框。统一映射到目标 token 网格，任何与像素区域相交的 token 均纳入，再按实际 token 数计预算。对越界/接触画面边缘的区域，记录裁剪后面积。结构扩展需要保存具体 mask PNG、token 索引及 hash。

默认步序：第 1 步全量建立缓存，第 2–7 步局部，第 8 步全量刷新。最后全量刷新可修复部分误差，但会消耗预算，不能从计时或模型调用数中删去。首次执行不扫很多时序；若默认时序质量明显失败，最多追加已预定的保守版本：全量步 `{1,2,4,6,8}`、局部步 `{3,5,7}`。保守版本单独计价、保留主结果，不能取较好结果替换失败主方案。

## 4 正确性硬门槛：先于性能结论

| 编号 | 检查 | 最小输入/方法 | 必须保留的证据 | 待执行 |
|---|---|---|---|---|

| C3 | 缓存隔离 | A→B→A 与 A→A；同一模型上 full→partial→full 和 partial→full→partial | 每请求 cache ID、清空事件、最终输出 hash/误差；请求开始前旧缓存不可读 | 是 |

| C7 | 动态新增活动位置来源 | 同请求内第1–4步使用R0，第5–8步使用R2（第1/8步仍全量） | 第5步新激活数等于R2减R0；新激活token从当前z_t重新经过img_in及所有block；不能从旧block输出或旧noise充当新计算 | 是 |

C1 应包含两级比较：先使用小模型/单 block 的 FP32 张量检查，再在真实模型 BF16 上检查每步 noise prediction、每步目标 latent 及最终 RGB。FP32 全选相对 L2 误差建议 ≤`1e-5`；BF16 则同时记录原生重复的数值噪声，优先要求canonical全选逐步latent一致。若有明确的kernel/精度路径差异而无法逐元素一致，逐步noise与latent误差上限暂定相对 L2 ≤`1e-3`、最大绝对误差 ≤`0.02`；图像误差只作补充，不能用最终图相似掩盖缓存或索引错误。任何超过原生重复误差的差异必须定位并记录，再决定是否允许进入部分路径。阈值是工程排错门槛，不是“无损”定义。

若实现可做到全选逐元素完全一致，应直接报告该结果，不把上述宽松门槛当作降低正确性的理由。若只能因 kernel 选择不同而近似一致，保留逐层误差，说明具体来源。

## 5 最小实验矩阵

为控制首轮成本，分两层执行。正确性门槛未过，不继续扩大矩阵。

### 5.1 执行器正确性与面积证据

| 组 | 路径与活动集合 | 目的 |
|---|---|---|
| F | 原生完整 8 步 | 本轮质量/性能基线 |
| G | 局部执行器、所有目标 token 全选，强制 gather/scatter | 验证语义与纯执行器开销 |

三个样例分别运行 F/G 的canonical全选检查，再对文字anchor运行reverse全选；另运行A→B→A请求级reset、衬衫R0→R2动态扩区和去发部分路径shape审计。以上为正确性诊断，不用其冷请求计时解释稳定性能。G不进入五重复性能矩阵，不提供稳定的G执行器开销中位数。

P25/P50专门面积扫描延期。R0在三个样例中约9%–28%的活动比例已提供低活动量诊断，实际比例以冻结mask清单为准；不因此声称完成精确25%面积或50%面积测试，也不拟合活动面积与时间的趋势。若低活动量仍无净收益，先剖析已有算子与缓存证据，不自动扩大扫描。

### 5.2 边界扩展对照

| 组 | 活动区选择 | 控制条件 |
|---|---|---|
| R0 | 冻结核心区域 | 最小目标区域，给出边界失败下界 |
| R1 | 核心区域在token网格固定扩展2格 | 核心必须全包含；显式登记L∞方形或其他结构，保持所有样例一致 |
| R2 | 人工结构polygon与核心取并集 | 沿接触/遮挡、对象完整轮廓扩展；只依据源图标注，预算冻结 |
| R3 | 与 R2 严格等 token 数的最近距离扩展 | 区分结构选择与面积增大；与 R2 使用同一时间调度 |

R2/R3 的活动 token 数必须完全相等。R3 按到R0核心区域的距离采用固定确定性排序；距离定义、并列规则与seed存入 `regions.json`。本轮允许按固定case+seed哈希打破距离并列，不能观察输出后挑seed或换排序。R2 必须包含 R0，R3 也必须包含 R0。R1 与 R3 相同可合并，不重复计为独立证据。若 R2 预算较 R0 未增加，不能描述为“扩展”；若 R2/R3 面积误差非零，重新匹配后再比较，不用百分比容差掩盖预算差。

结构扩展应明确示例中的依据：文字木块的完整局部载体与桌面接触；衬衫与手、头发、衣领的接触关系；发丝与盘沿、叉子的接触。R2是人工预给结构区域，**不属于已实现的自动策略或可学习创新**。仅把允许变化粗框当结构 mask 不足以证明“最清晰边界”，可以作为人工框启发式下界。

主性能矩阵固定为 **F/R0/R1/R2/R3 × 3样例 ×（预热1次 + 正式计时5次）=90请求**，即15条预热、75条计时。预热不进入性能均值/中位数。每个样例的每次重复都将五个配置的执行顺序循环轮换：第0轮F/R0/R1/R2/R3，第1轮R0/R1/R2/R3/F，以此类推，避免固定顺序偏差。所有计时包含请求级缓存建立、清理及GPU同步；ROI预先给定，离线mask制作耗时不混入请求时间，另说明未来自动策略需计价。

上述90请求之外，现计划正确性诊断12请求：三个样例F/G共6、文字reverse全选1、A-B-A重置3、动态扩区1、部分shape审计1；合计初始主计划102请求/816次DiT（每请求8次），不含微型测试与尚未触发的保守刷新诊断。若因失败中断，按真实成功/失败/未执行分别报告，不补造完整数。

若同一静态配置五次输出hash一致，质量指标只计一个样本，不把五次计时当作五个质量样本。若实际执行少于五次重复，登记协议偏离且不宣称达到五次性能门槛。各配置均保留全部输出hash，不挑最快一次。

## 6 算子与缓存证据

每个目标/条件/文本分支分别登记：总 token、活动 token、fresh token、stale token，缓存 age（距最后刷新多少步），缓存读/写字节、缓存存储 dtype，是否有全图投影后再 gather 的情况。至少对一个低比例样例的全部8步、首/中/末 block 记录真实输入形状。

必要 shape 字段：`image_to_q_in`、`image_to_k_in`、`image_to_v_in`、`text_qkv_in`、joint `Q/K/V`、`image_to_out_in`、`image_mlp_in`、`text_mlp_in`、gather/scatter 输入输出、final projection。所有计数均注明 image 中目标/条件的组成。

如果只减少 Q 而 K/V 全量重算，必须写为“局部 Q + 完整 KV”；如果只省目标 MLP，应写为对应算子收益。若只是完整 DiT 后将输出 mask 合成，计算并未局部化，不能算完成执行器。

缓存成本分三项记录：①首步全量建立与分配；②局部步的读取、索引、重排、更新；③末步/中间刷新。报告缓存 tensor 唯一 storage 字节和峰值显存，避免将 view 重复相加；日志只保存 shape/hash，不保留巨大中间张量引用。跨请求测试中缓存应真正释放或复用为已清空状态，不计量化/offload收益。本轮只验证请求级reset与同请求R0→R2新增token，不实现去噪中途缓存快照/分支clone；后者不得出现在已完成清单中。

时间记录至少包括完整请求、DiT、边界/掩码生成与搬运、gather/scatter、KV 更新/拼接、刷新。CUDA events 区间测量不能简单与主机墙钟相加；开销较小的操作可合并成事件区间并说明。主性能路径关闭逐层 hooks，另跑一次带 hooks 的 shape 审计；这样避免把大量 Python hooks 的开销当部署性能。保留无插桩端到端对照。

## 7 质量检查与边界指标

质量以完整 Lightning F 为近似参照，同时对源图测保持性，并人工核对编辑指令。不得仅凭相对 F 的 LPIPS 低而认定编辑成功。

统一报告全图 MAE、PSNR、SSIM、LPIPS-mapmean；核心区域、固定公共边界带、远背景的 MAE/特征距离；成功/失败与具体伪影。区域 LPIPS 为全图特征距离图内均值，感受野跨区域，不冒称独立区域 LPIPS。不要先把 mask 外 RGB 涂黑再套全图指标。

为公平比较 R2/R3，**评价区域必须固定且与策略无关**：①同一个核心 R0；②围绕冻结参考边界的公共窄带；③相同允许变化框外部。另可画各策略实际活动边界的诊断热图，但不能以各自不同边界带的均值判断谁更好。窄带宽度以目标 token 网格的1/2/4格定义，映射回像素时存实际宽度；三条窄带分别报告，不能相加。

建议补充边界梯度误差：在固定公共窄带，比较相邻像素梯度相对 F 的偏差，并报告该梯度指标的方向和归一化。梯度大本身不代表接缝，真实轮廓也会高；必须结合边界放大图看是否截断、复制、错位、颜色跳变。

三个任务的非盲初查项目分别为：目标短语完整/字序/木块结构；浅蓝换色完成/手部与发丝/身份与衣领；头发是否仍可见/盘沿与叉子完整/菜单保持。本轮不能宣称盲评成功率。所有失败样例和所有配置输出一并归档。

## 8 预设去留门槛

以下门槛只决定是否投入下一轮扩大验证，不用于论文质量声明。任何调整必须写变更原因与时间，不看输出后移动门槛。

| 决策 | 本轮条件 | 后续动作 |
|---|---|---|
| Correctness Go | C0–C7通过，全选路径满足数值门槛，cache隔离通过，实际重算token与配置一致 | 才解释部分路径的速度/质量 |
| Executor Go | 至少2/3样例在R0或其他低活动比例配置上，完整请求5次中位数比F下降≥10%；各样例配对速度趋势一致，无新增OOM；真实昂贵算子缩减且收益覆盖全部缓存/索引成本 | 保留执行器，扩大验证数据 |
| Boundary Go | R2/R3严格等token；R2在至少2/3样例的公共边界MAE改善≥10%，梯度指标作辅助；编辑指令不劣且没有新严重伪影；另一个样例无超过10%的明显指标恶化；R2净性能仍达标 | 收集8/16/32小样本，研究区域选择头 |
| Revise | 内核/索引正确，但速度下降0–10%；或仅DiT加速、端到端无收益；或R2/R3同预算无稳定质量差异 | 针对固定条件/文本成本、索引、小矩阵或区域定义仅做一轮有依据改进 |
| Stop或换切入点 | 全选误差无法排除；或活动比例≤25%仍稳定更慢且成本剖析显示固定项主导；或质量只能靠大面积/频繁刷新挽救，导致全部净收益消失 | 暂停训练/RL，评估只优化MLP、层选择或其他系统优化 |

Boundary Go 还需满足探索性保真筛查：相对 F 全图 LPIPS-mapmean增量≤0.02、远背景MAE增加≤`1/255`，并逐样例列出。阈值不是感知等价或非劣性证据；指标低于门槛但出现文字丢失、对象截断、接缝、身份明显变化时仍判为失败。若 F 本身任务失败，该样例只用于执行器性能，不用于证明边界策略有效。R2/R3的10%相对改善在R3公共边界误差接近零时记N/A，另报绝对差，不能用极小分母制造明显改善；若不足两个有效样例，不判Boundary Go。

三样例的2/3只是工程投资判断。若 R2/R3 只在其中一例改善，应写“有个案线索”，进入更多开发样例验证，而不是认定创新已经成立。达到本轮 Go 后，下一轮至少增加10–20个独立开发输入与多个种子，再冻结策略和正式评价；正式 Train/Val/Test 的规模与盲评需单独预注册。
