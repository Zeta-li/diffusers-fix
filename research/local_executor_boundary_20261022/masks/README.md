# 本轮冻结的计算区域

生成脚本：[prepare_regions.py](../scripts/prepare_regions.py)。清单：[regions.json](regions.json)。源图与掩码预览：[全部输入](../figures/regions_all_cases.png)。

这里的区域用于决定重新计算哪些目标图 token；它们不是编辑 mask，也不会改变输入图或提示。条件图 token 与 text token 始终计算。本轮只有三个公开演示输入，没有使用正式 Train / Val / Test。

| 输入 | 目标 token 网格 | R0 核心 | R1 固定膨胀 | R2 人工结构扩展 | R3 等预算普通扩展 |
|---|---|---:|---:|---:|---:|
| blocks_text | 52 × 78 | 988（24.36%） | 1288（31.76%） | 1088（26.82%） | 1088（26.82%） |
| shirt_color | 52 × 78 | 1150（28.35%） | 1350（33.28%） | 1282（31.61%） | 1282（31.61%） |
| remove_hair | 64 × 64 | 372（9.08%） | 560（13.67%） | 438（10.69%） | 438（10.69%） |

R0 保守覆盖旧实验已经冻结的 core_box；一个 token 与该框相交即纳入。R1 对 R0 做固定 2-token 的 Chebyshev 膨胀。R2 将 R0 与源图手绘的木块阴影/纸面、衣服与头发/袖缘、盘沿与叉尖接触区域合并。R3 保留全部 R0，按距离核心矩形的欧氏距离由近及远加入 token；距离相同时按固定种子与 case/坐标的 SHA256 排序，直到恰好达到 R2 的目标 token 数。

R2 是**人工结构先验可行性诊断，不是自动选区方法或创新性证明**。本轮区域在新局部运行的输出查看之前冻结，但研究者已经见过旧的完整/Lightning 基线输出，所以不声称是盲标。脚本只打开源图，旧运行日志仅提供实际网格与 token 长度；不读取任何生成图像来调整区域。

R2/R3 保证相同核心、相同活动目标 token 数、相同完整条件与 text 上下文。运行时还必须保持相同刷新与缓存规则。两者的周长、紧凑性与结构位置未被单独控制，清单已记录周长与连通分量；R3 的距离并列项只取部分时会形成单 token 的锯齿。这些差异限制了因果解释，不能将任何质量差距完全归因于“语义边界”。R1 是固定规则的辅助参照，其预算没有强制与 R2 相等。

比例表仅为目标 token 比例。加入始终计算的条件图和旧正向 text token 后，R2/R3 的总 query 比例分别约为 68.72%、70.74%、61.80%。真实 DiT 计算还受完整 K/V、投影、归一化、索引和实现方式影响，不能按目标区域百分比直接推算加速倍数。

GPU 脚本可读取 `cases[case_id].regions[region_id].indices`，其为排序后的目标图 row-major 索引，`index = row * grid_width + column`；也可按 `mask_npy` 相对路径读取布尔二维数组。清单中的索引均只针对目标图，不包含拼接后的条件图索引或 text 索引。每个 token 对应本轮 16 × 16 个目标像素。

生成后已核对 12 个掩码的形状、布尔类型、核心包含、索引一致性、非空且非全图、R2/R3 严格等数并存在差异。源图、旧 ROI 和各 `.npy` 文件的 SHA256 均写入清单。
